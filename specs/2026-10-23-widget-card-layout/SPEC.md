# 浮窗固定卡片与自动换行

## 需求与边界
服务卡片保持统一尺寸，根据浮窗内容区宽度自动增减列数；不再固定四列。保留服务顺序、状态、主题、滚动、拖动及尺寸记忆。仅修改浮窗布局，不涉及矩阵、探测接口或服务端。

## 调研结果与方案
现有 `.km-ul-logo-grid` 使用 `repeat(4, minmax(0, 1fr))`，导致窄窗挤压、宽窗拉伸。采用 CSS Grid `repeat(auto-fill, 94px)`，卡片固定 94 × 108px，名称采用 16px 等宽字体，以 8 字符 Bilibili 刚好完整显示为基准，间距 10px，末行左对齐。列数取决于实际内容宽度，剩余空间保留在右侧；高度变化仅影响可见行数。
最小浮窗宽度约 348px，包含三列卡片、两处间距、左右内边距、边框和滚动条预留；滚动条使用稳定占位，避免高度变化时列数抖动。当视口本身不足时允许缩窄，优先保证浮窗不溢出。正式实现需同步 CSS、拖动手柄和恢复尺寸时的最小宽度。
静态原型：`docs/prototype/widget-card-layout.html`。原型示例状态不进入生产数据路径。视觉确认后再修改生产代码。

## 默认宽度与主题修复
首次展开默认宽 452px，刚好容纳四列（含滚动条预留），后续继续使用用户保存尺寸；最小宽 348px 为三列。视口不足时优先保证不溢出。CSS 统一定义宽度变量，JS 定位与缩放均读取同一最小宽。顶部按钮采用与标题相同的 `--km-ul-text`，避免浅色皮肤下继承浅色次要文字。用户连续明确卡片尺寸、最小三列和首次四列的要求，按已确认方向应用到正式浮窗。

## 数据流与接口
继续使用原有快照和渲染逻辑，无新增请求或接口。

## 验证计划
- Unit：无新增纯函数；生产修改后执行现有离线测试和原生 JS 语法检查。
- Module：浏览器实测 320/440/680/980px 浮窗下卡片尺寸恒定、列数递增、无水平溢出、顺序不变；确认窄视口规则不覆盖布局。
- Integration：本地打包后由用户安装到真实 Komari 实例，验证拖动缩放、主题同步、状态显示与尺寸记忆；用户确认后才允许推送。
